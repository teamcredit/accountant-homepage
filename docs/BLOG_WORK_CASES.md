# 업무 경험 글 쓰는 법

> 쉬운 요약: 이 문서가 요약본입니다. 더 줄일 게 없습니다.

## 이게 뭔가

「업무 경험」은 **실제로 한 일**을 적는 갈래입니다.
해설 글(판례·세액공제 같은 것)과는 읽는 목적이 다릅니다.

- 해설 글 → 「이 제도는 이렇습니다」
- 업무 경험 → 「이 일을 이렇게 했습니다」

디자인검토 #62 가 정한 틀입니다.

## 어디에 나오나

한 편을 쓰면 두 군데에 같이 섭니다.

| 어디 | 조건 |
|---|---|
| `/blog?cat=case` 목록 | `category: 업무경험` |
| 서비스 상세 아래 「업무 경험」 칸 | `services:` 에 그 서비스를 적었을 때 |

`services` 를 안 적으면 목록에만 서고 서비스 쪽에는 안 붙습니다.
아무 서비스에나 붙는 것보다 안 붙는 편이 낫다고 봤습니다.

## 어떻게 쓰나

`content/posts/` 에 `.mdx` 파일 하나를 만듭니다.
파일 이름이 곧 주소입니다 — 영문 소문자와 붙임표만 씁니다.

```
content/posts/manufacturer-bookkeeping-handover-2026.mdx
→ /blog/manufacturer-bookkeeping-handover-2026
```

머리말은 이렇게 적습니다.

```yaml
---
title: '제조업 A사 기장 이관 — 3년치 계정 오분류를 다시 잡은 일'
description: 넘겨받은 장부에서 대표 급여와 법인카드가 섞여 있던 건을 어떻게 갈랐는지 적습니다.
date: '2026-09-10'
category: 업무경험          # ← 이 줄이 있어야 업무 경험 갈래로 갑니다
services:                   # ← 어느 서비스 이야기인지
  - tax-bookkeeping
published: true
author: 박민상 회계사
keywords:
  - 기장 이관
  - 계정 오분류
---
```

### services 에 쓸 수 있는 값

서비스 주소의 뒷조각입니다. `src/lib/constants.ts` 의 `serviceGroups` 가 원본입니다.

| 분류 | 값 |
|---|---|
| 세무자문 | `tax-bookkeeping` · `tax-adjustment` · `payroll-outsourcing` |
| 회계감사 | `audit-advisory` |
| 회계자문 | `pa` · `ipo-advisory` |
| 재무자문 | `transaction-advisory` · `valuation` |

여러 서비스에 걸치면 여러 개를 적어도 됩니다.

## 본문 차례

디자인검토가 정한 순서입니다. 이 넷을 소제목으로 씁니다.

```markdown
## 의뢰 배경
## 주요 검토
## 작성 자료
## 정리 결과
```

## 주의

- **고객사 이름을 그대로 적지 않습니다.** 「제조업 A사」, 「매출 80억대 도매업체」처럼 씁니다.
- 금액은 범위로만 적습니다.
- 계약서에 비밀유지 조항이 있으면 그 건은 아예 쓰지 않습니다.
